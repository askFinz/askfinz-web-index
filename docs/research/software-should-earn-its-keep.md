## Key points

### Software should earn its keep

A demo shows you the first time you use something. Real work is the hundredth.

### What the demo structurally cannot show

The problem with optimising for demonstrations is not that demos are dishonest. Most are not.

### The gap between output and finished

Producing output is not the hard part any more. Finishing is.

### The metric we tried and threw out

The obvious way to hold yourself to this is to measure it, so we tried to.

### Reliability does not photograph well

There is a class of properties that make software trustworthy and essentially never appear in a launch: consistent formatting across a hundred uses. Citations that land on the right sentence.

### Where this principle bites us

"Does it help someone finish" is conservative, and conservatism has a cost. The question is very good at rejecting things and quite bad at proposing them.

### What we would do differently

We would have looked at the hundredth run before we polished the first.
